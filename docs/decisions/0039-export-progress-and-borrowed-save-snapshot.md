# DXF 진행 상태와 저장 스냅샷의 메모리 수명

## 결정

데스크톱 DXF 내보내기는 파일 선택 직후부터 완료 또는 실패까지 Qt 모달
오버레이를 띄워 프로젝트 편집 입력을 막는다. 브리지에서는 저장 요청 세대와
내보내기 상태 세대를 함께 전달해 이전 요청의 상태가 새 요청의 오버레이를
닫지 못하게 한다. 레이어별 시작, 배치별 처리 피처 수, 레이어 완료 및 전체
결과를 진행 문구와 제한된 진단 로그에 기록한다. 피처 수는 필터를 통과해
DXF writer에 전달된 수이며 전체 피처에 대한 백분율로 표시하지 않는다.

공용 명령 API의 전체 또는 단일 레이어 저장은 writer가 읽기 전용 차용 계약을 명시한
경우에만 피처 헤더를 복사하고 WKB와 속성 맵을 공유한다. GDAL writer는
호출 중 이 데이터를 변경하거나 호출 뒤 보유하지 않는다. 그 외 writer에는
기존의 완전 복제 스냅샷을 전달한다.

기존 GeoPackage의 한 레이어를 갱신할 때는 새 파일에 변경 레이어를 쓰고,
나머지 레이어는 GDAL `CopyLayer`로 복사한 뒤 원본과 교체한다. 레이어 전체를
Go 피처로 읽지 않는다. 취소는 레이어 복사 사이에 확인하며, 실행 중인
단일 GDAL 복사 호출은 그 호출이 반환된 후 취소된다. 오류 시 임시 파일을
삭제하고 기존 파일은 보존한다. 복사에 쓰는 원본·임시 GDAL dataset은 이 호출
안에서만 사용하고 닫으며 다른 작업 스레드와 공유하지 않는다.

## 근거와 영향

큰 프로젝트의 저장 직전에 WKB와 속성 맵을 다시 복제하면 실제 쓰기와
무관한 메모리 최고점이 커진다. 차용 계약은 드라이버 경계에서 수명을
명확히 하면서 기존 사용자 정의 writer의 독립 스냅샷 보장을 유지한다.
내보내기 상태를 렌더 상태와 분리하면 진행 중 편집 입력과 완료 상태가
교차하는 문제를 줄인다. DXF와 GDAL 데이터셋은 성공·오류 경로에서 닫는다.

SHP 화면 표시 규칙은 GDAL 공간 창 조회 뒤 렌더용 피처 배열에 적용한다.
규칙 평가에는 속성이 필요하므로 조회된 창의 숨김 피처도 일시적으로
메모리에 들어오지만 렌더 정점·선택 대상·레이블에는 들어가지 않는다.
필터 뒤 배열의 남은 참조를 지우고, 창이 화면 밖으로 나가면 관련 캐시를
제거한다. 원본 레이어와 DXF 내보내기에는 별도 경로로 동일한 규칙을 적용한다.
