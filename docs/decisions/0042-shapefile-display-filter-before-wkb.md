# SHP 표시 필터를 WKB 복사 전에 적용

## 결정

읽기 전용 SHP의 화면 창을 읽을 때 공간 필터로 찾은 피처의 속성을 먼저
디코딩하고 표시 규칙을 평가한다. 숨길 피처는 WKB 복사, 화면 창의 피처
슬라이스, 정점·라벨·히트 대상에 넣지 않는다. 창의 피처 수와 디코딩
페이로드 한도는 표시할 피처에 적용한다. 필터 결과가 희소한 일반 창은
작은 피처 슬라이스로 시작하며, 기존 필터 단계도 큰 빈/희소 슬라이스의
백킹 배열을 놓는다.

한 번의 창 조회가 한도를 넘으면 새로운 Lua 프로그램으로 다시 시작해
기존 분할 조회 및 지문 기반 중복 제거를 사용한다. 이는 분할된 창에서
동일 피처의 표시 규칙이 여러 번 평가되지 않던 동작을 유지한다.

## 드라이버 경계

`AttributeSession.OpenShapefileWindowWithLimitsFiltered`는 세션 잠금을
유지한 채 GDAL 결과셋을 읽는다. 각 GDAL 피처와 SQL 결과셋은 기존
`defer Close` 경로에서 닫고, 실패·취소 시에는 부분 레이어를 반환하지
않는다. 호출자는 실패한 읽기를 재시도할 때 규칙 프로그램을 새로 만들어야
한다. 프로젝트의 원본 피처와 DXF 내보내기용 데이터는 이 화면 창 처리로
변경하지 않는다.

## 검증

SHP에서 숨긴 피처가 화면 창의 피처 한도를 소모하지 않고, 표시할 피처의
원래 조회 ID와 속성·도형이 유지되는지 테스트한다. 개요 및 상세 렌더
테스트와 희소 창의 백킹 배열 해제 테스트도 함께 실행한다.

Apple M3의 SHP 점 1만 개 중 100개를 표시하는 같은 창 조회를
`-benchtime=300ms -benchmem`으로 측정했다. 기존 읽기 후 필터는
13.15 ms/op, 10.84 MB/op, 170,030 allocs/op였고, 읽는 중 필터는
9.97 ms/op, 8.99 MB/op, 100,730 allocs/op였다. 벤치마크의 속성
조건은 단순 비교이므로 실제 Lua 규칙과 복잡한 도형의 효과는 별도
데이터에서 다를 수 있다.
