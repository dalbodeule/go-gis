# ADR 0038: 넓은 화면의 피처 제한과 레이어별 Lua 설정

## 배경

공주시 범위에서 읽기 전용 화면의 300,000피처 상한에 닿아 일부 청크가 표시되지
않았다. 동시에 레이어 목록의 QML 모델이 서버에서 받은 `displayRule`을 누락해,
레이어 속성을 다시 열면 저장된 표시 필터가 빈 값으로 나타났다.

## 결정

- 읽기 전용 화면의 누적 피처 상한을 500,000개로 늘린다. 개별 공간창의
  드라이버 조회당 20,000피처/32 MiB 제한은 유지한다. 화면 전체와 분할 조회를
  합친 청크의 추정 payload 예산은
  기본 512 MiB로 올리고 설정에서 1~4,096 MiB 또는 0(제한 없음)을 선택한다.
  이 수치는 실제 프로세스 RSS 제한이 아니며 더 조밀한 자료에서는 다른 예산에
  먼저 닿을 수 있다.
- 분할 조회는 개별 조회의 32 MiB를 넘는 결과도 합칠 수 있다. 합친 청크의
  추정 payload와 피처 수에는 화면 설정의 상한을 적용한다. `0`이면 합친
  청크의 추정 payload 상한도 해제하지만 조회 횟수, 개별 조회 크기,
  지오메트리 복잡도와 렌더러 제한은 유지한다.
- 앱 설정에서 이 상한을 50,000~1,000,000 사이로 조절할 수 있게 한다.
  기본값은 500,000이며 Qt 사용자 설정에 저장한다. 변경하면 현재 화면을 다시
  그린다. 잘못된 저장값은 기본값으로 되돌린다.
- QML 레이어 모델에 `displayRule`을 포함하고, 속성 창은 선택한 레이어의 이름으로
  설정을 읽는다. Lua 탭을 바꾸면 현재 코드가 해당 레이어 설정 초안에 반영되고,
  Lua 편집기 확인은 세 코드를 함께 레이어 설정 요청으로 전송한다. 취소하면
  편집기에서 변경한 초안을 복원한다. 적용/확인 버튼은 취소 버튼 오른쪽에 둔다.

## 검증 범위

경계값 단위 테스트와 두 레이어의 서로 다른 표시 필터를 사용하는 QML 테스트를
추가한다. 사용자 업무 자료를 저장소에 추가하지 않는다. 공주시 실제 자료의
완료 시간과 메모리 사용량은 해당 자료가 있는 환경에서 다시 확인해야 한다.
