# 렌더 색상 변환을 레이어당 한 번 수행

## 결정

레이어 렌더 소스를 만들 때 채움·점·선 색상을 각각 한 번 해석하고,
생성된 정점에는 이미 해석한 정수 색상을 적용한다. 스타일과 레이어의
도형 종류는 이 단계에서 변하지 않으므로 정점마다 `#RRGGBB` 문자열을
다시 디코딩할 필요가 없다. 기존 색상 선택 및 기본값 규칙은 유지한다.

## 근거와 측정

CPU 프로파일에서 `ColorForGeometry`, `styleColor`, `hex.DecodeString`이
정점 수만큼 호출되는 비용이 확인됐다. Apple M3, Go 1.27.3에서 기존
벤치마크를 같은 조건(`-benchtime=300ms -benchmem -cpuprofile`)으로 비교한 결과:

| 작업 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| WKB 폴리곤 1만 개 렌더 소스 | 27.9 ms, 800,260 할당 | 7.6 ms, 263 할당 |
| 점 10만 개 렌더 소스 | 16.8 ms, 400,034 할당 | 9.0 ms, 40 할당 |

두 측정은 프로파일 생성 및 시스템 상태에 따라 달라질 수 있다. GDAL/PROJ/GEOS
호출은 별도 드라이버 경계에 남기고, 외부 라이브러리를 피처마다 새로 여는
변경은 이 결정에 포함하지 않는다.
