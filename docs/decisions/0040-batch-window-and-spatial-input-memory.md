# 배치 읽기, 필터 창, 공간 연산 입력 메모리

## 결정

GDAL `ReadBatches`의 피처 배열은 콜백 반환 후 전체 참조를 지우고 다음
배치에 재사용한다. 콜백은 배치를 반환 후 보유할 수 없다는 기존 계약을
명시한다. GDAL 피처와 dataset은 성공·오류·취소 경로에서 닫는다.

읽기 전용 화면 창은 SHP 등에서 GDAL 공간 조회가 끝난 직후 표시 규칙을
적용한다. 창이 밀집하여 하위 창으로 분할되면 각 하위 창의 숨김 피처를
합산 배열에 넣지 않는다. 중복 판별을 먼저 수행해 경계에 걸친 피처의
Lua 규칙 평가 횟수를 유지한다. 중복 판별표는 숨김 피처까지 최대 100만 개의
고유 지문으로 제한한다. Lua 규칙은 창 빌드마다 한 번 컴파일하고 하위 창
평가에 재사용한다. 원본 프로젝트 데이터는 수정하지 않으며, 조회 자체의
피처·바이트 한도와 분할 횟수 한도는 유지한다.

공간 연산자는 입력 형상·속성·레이블을 변경하거나 보유하지 않는다는
계약을 명시적으로 구현할 수 있다. 이 경우 공용 명령 API는 피처 헤더만
복사하고 입력 페이로드를 공유한다. GEOS 연산자가 이 계약을 구현한다.
다른 연산자는 기존의 완전 복제 입력을 받는다. GEOS context는 연산자
인스턴스별로 유지하고, 동시에 여러 작업 스레드에서 공유하지 않는다.
한 화면 창에서 dissolve와 단순화를 연속 실행할 때는 같은 연산자를 사용한다.
점 레이어는 단순화 대상이 아니므로 이 단계의 GEOS context 생성도 건너뛴다.

## 근거와 검증

DXF 배치 읽기는 배치마다 새 피처 배열을 만들던 할당을 줄인다. 표시 규칙이
많은 SHP 피처를 숨길 때는 하위 창 병합 전에 도형·속성 참조를 제거해
일시적인 Go 메모리를 줄인다. 1만 피처의 공간 연산 입력 스냅샷
벤치마크에서 완전 복제는 약 3.9 MB·30,002 할당, 차용 스냅샷은 약
0.4 MB·2 할당이었다. 이 수치는 입력 준비 비용이며 GEOS 계산 전체의
메모리 사용량을 뜻하지 않는다.
