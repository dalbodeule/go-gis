# 초기 화면 레이아웃 전 렌더 보류

## 관찰

공주시 작업공간의 사용자 로그에서 QML 지도 크기가 `0×0`일 때
296개 청크의 요청이 시작되고 첫 배치 115,437정점이 만들어졌다.
실제 지도 크기 `1172×732`가 도착하면 그 요청은 취소됐다. 같은
크기와 확대율의 요청도 약 133 ms 간격으로 두 번 시작됐다.

## 결정

읽기 전용 데이터의 현재 화면 갱신은 캔버스와 화면의 크기 및 확대율이
유효할 때 시작한다. 초기 QML 레이아웃은 네이티브 캔버스의 화면 세대
번호를 올리므로, 크기가 준비되면 기존 동기화 루프가 렌더를 요청한다.
화면 크기가 아직 없으면 동기화 루프는 요청을 보류한다.

동일한 렌더 스케줄러에서 0.25 화면 픽셀 이하의 팬·크기 차이와
사실상 같은 확대율을 가진 연속 QML 화면 세대는 중복 요청으로 본다.
레이어 가시성 변경, 스케줄러 교체, 표시 피처·바이트 한도 변경은
동일한 화면 좌표라도 다시 렌더한다. 실제 팬·확대·크기 변경은 계속
새 렌더 세대를 만든다.

## 검증

유효하지 않은 초기 크기, 작은 레이아웃 오차, 한 픽셀 팬, 확대율과
화면 크기 변화를 단위 테스트로 확인한다. Qt/native 테스트와 QML
화면 테스트를 실행한다. 실제 업무 파일은 읽기만 하고 저장소에 넣지 않는다.
