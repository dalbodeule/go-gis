# 첫 가시 화면 게시와 로그창 위치

## 관찰

공주시 지적도, 충남 도근점, 건물정보의 사용자 로그에서는 QIX 인덱스를
세 소스 모두 사용했으며 최종 요청은 428개 청크 중 74개에 정점을
포함했다. 첫 정점 게시가 요청 완료 약 25.8초 뒤에야 나타났다. 기존
읽기 전용 게시 한도는 비어 있는 중간 게시도 횟수에 포함했고, 첫
가시 청크가 30,000정점을 넘으면 그 청크도 최종 게시까지 보류했다.

도근점 SHP 헤더의 전체 범위는 (0, 0)–(3,756,018.1, 4,294,793.53)이다.
지적도 범위보다 훨씬 넓어 정규화된 전체 좌표계에서 도형이 작은
영역에 몰린다. 기존 `center_vertices` 및 `occupied_cells`는 화면이
아닌 이 전체 정규화 좌표계를 기준으로 한 값이었다.

사용자가 지정한 작업공간을 읽어 도근점 표시 규칙은 `COL_ADM_SE`의
`44150` 일치, 건물정보 표시 규칙은 `A3`의 앞 5자리가 `44150`인지
검사함을 확인했다. 읽기 전용 OGRSQL로 같은 속성 조건의 건수를 세면
도근점은 153,502개 중 13,337개, 건물정보는 1,000,000개 중
104,454개다. 이는 파일 전체의 속성 조건 건수이며 한 화면의
가시 피처 수는 아니다.

## 결정

읽기 전용 지도에서 첫 가시 배치는 중간 게시의 정점·횟수 한도와
무관하게 게시한다. 이후 게시에는 기존 한도를 적용하고, 빈 배치는
게시 횟수에 넣지 않는다. 기존 완성 화면을 유지하는 교체 요청은
계속 최종 결과를 기다린다.

렌더 진단에는 표시 규칙이 설정된 레이어 이름과 레이어별 정점·비어
있지 않은 청크 수를 기록한다. 규칙 원문은 로그에 쓰지 않는다.
전체 범위 기준 진단 이름은 `world_center_vertices`,
`world_occupied_cells`로 명확히 한다.

로그창은 열릴 때와 새 텍스트·레이아웃이 들어올 때 가로 위치를 0,
세로 위치를 맨 아래로 맞춘다. 새 로그가 없으면 사용자의 수동 스크롤을
유지하며, 창 크기가 바뀌면 새 크기에 맞춰 위치를 다시 맞춘다.

## 검증

30,001정점의 첫 청크가 다른 청크보다 먼저 게시되는 통합 테스트와,
긴 줄·여러 줄의 로그가 좌측 하단에 표시되는 QML 테스트를 실행한다.
실제 작업공간의 상세 창 표본 120개도 모두 빌드됐고 1,977,574개
정점, 건물 채움 정점 36개, 투명 채움 정점 0개를 확인했다.
같은 작업공간의 저장된 화면 상태로 428개 청크 전체를 새로 렌더한
통합 테스트에서는 첫 가시 배치를 259 ms에 게시했고, 최종 완료는
33,377 ms였다. 비어 있지 않은 청크는 건물정보 24개, 도근점 24개,
지적도 26개였고 건물 채움 정점은 998,652개였다. 전체 정점 수는
8,504,404개로 사용자가 제공한 기존 로그와 같았다. 기기 상태에
따라 절대 시간은 달라질 수 있다.
실제 업무 파일은 읽기만 했고 저장소에 복사하지 않았다.
