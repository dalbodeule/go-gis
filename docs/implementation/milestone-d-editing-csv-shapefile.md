# 마일스톤 D 보완 검토 — 편집 잠금, CSV 도형 생성, SHP 납품

작성: 2026-10-24 / 상태: 구현 가능성 검토 및 요구사항 설계 완료, 신규 기능 구현 전

## 결론과 현재 근거

요청한 레이어별 Lock/Unlock, CSV/TSV 점 추가, 선택한 점으로 닫힌 도형 생성,
자동 레이블 데이터 생성, 기존 데이터의 SHP 변환은 현재 구조를 확장해 구현 가능하다.
다만 기반 코드의 존재와 사용 가능한 전체 업무 흐름의 완성은 구분한다.

| 요구 | 확인한 코드 근거 | 추가할 부분 |
| --- | --- | --- |
| 레이어별 도형 편집 잠금 | `internal/core/model.go`의 `Layer.Editable`, `internal/commands/project.go`의 편집 트랜잭션 및 쓰기 가능 여부 검사 | 편집 가능 여부와 별개인 사용자 잠금 상태, 기본값, 공용 명령 차단, 잠금 버튼 및 전환 처리 |
| 도형 추가·편집·삭제 | `ProjectService.AddFeature`, `SetFeatureGeometry`, `DeleteFeature`; `cmd/gis-desktop/main_qt.go`의 `addFeature`, `moveSelectedVertex` | 빈 레이어 생성, 지도 입력 도구, 선택 삭제, 일관된 저장/취소/실행 취소와 잠금 검사 |
| CSV/TSV 점 추가 | D1에 입력 매핑·인코딩·CRS·오류 처리 계획 존재 | 표 입력 드라이버, 미리보기, 점 생성 공용 명령과 GUI/CLI 연결 |
| 선택한 점의 닫힌 도형 | 기존 geometry 모델·렌더러·GEOS 경계 재사용 가능 | 순서가 있는 점 선택 모델, 폴리곤 생성·검증 명령, 연결선 미리보기 |
| 레이블용 데이터 생성 | `Layer.Labels`, `Feature.Label`, `runtime_native_qt.go`의 `prepareLayerLabelsCoreWithBudget` | 점번호/템플릿의 문자열 속성 생성, 중복/빈 값 정책, 내보낼 속성과 표시 설정 연결 |
| SHP 내보내기 | `drivers/gdal/writer.go`에 `.shp` 드라이버 선택과 UTF-8 `.cpg` 생성, `writer_test.go`에 왕복/다중 레이어 거부 테스트; CLI 출력 경로 존재 | GUI의 명시적 레이어 내보내기, 필드 매핑/손실 사전 안내, 파일 묶음 저장 안전성, 빈 레이어·인코딩 옵션 보강 |

이 검토는 새 입력 방식과 UI의 실행 성공을 증명하지 않는다. 기존 SHP writer는
첫 피처에서 형상 타입을 추론하므로 빈 레이어 출력은 현재 거부한다. 모든 피처의
형상 타입이 동일해야 하며 SHP 한 세트에 여러 레이어를 쓰는 것도 거부한다.

## 1. 레이어 Lock/Unlock 및 도형 편집

### 상태와 기본값

`Editable`은 데이터 소스·로딩 방식이 쓰기를 지원하는지를 나타내는 능력으로 유지하고,
별도의 `GeometryLocked`에 해당하는 사용자 정책 상태를 둔다. 실제 도형 변경은
`소스 쓰기 가능 && 잠금 해제 && 해당 레이어의 편집 작업 유효`일 때만 허용한다.
잠금은 보안 권한이나 DB 동시 편집 잠금을 대신하지 않는다.

| 상황 | 초기 상태/전환 |
| --- | --- |
| 기존 파일·DB·CSV에서 불러온 레이어 | 기본 Lock. 편집 가능 소스만 명시적으로 Unlock 가능 |
| 사용자가 새로 만든 빈 편집 레이어 | 형상 종류·CRS·필드 정의 후 Unlock으로 시작 |
| 쓰기 가능한 소스에서 전체 피처 수 0을 확인한 빈 레이어 | Unlock으로 시작 |
| 전체 개수가 미확정이거나 화면/필터 결과만 0인 레이어 | 빈 레이어로 판단하지 않고 Lock 유지 |
| 대형 viewport 읽기 전용 레이어·권한 없는 DB | Lock, 해제 불가 이유 표시. 필요 시 범위를 새 편집 레이어로 복사 |
| 빈 레이어에 첫 도형을 추가하거나 마지막 도형을 삭제 | 현재 상태 유지. 피처 수 변화로 자동 잠금/해제를 반복하지 않음 |
| 작업공간 재개방 | 안전한 기본값을 재적용: 데이터 있는 레이어 Lock, 확인된 쓰기 가능 빈 레이어 Unlock. 이전 Unlock을 자동 복원하지 않음 |

레이어 목록에 자물쇠 아이콘과 상태 설명을 표시한다. Lock에서도 지도 이동·선택·조회,
표시 스타일·레이블 설정·별도 내보내기는 가능하다. 이번 잠금은 도형 편집에 한정한다.
기존 속성 편집 권한은 `Editable` 정책을 따르고 UI에서 적용 범위를 설명한다.
피처 삭제는 속성도 함께 사라지므로 반드시 도형 잠금의 통제를 받는다.

### 편집과 전환 규칙

- 새 레이어는 Point/LineString/Polygon 중 형상 종류와 CRS를 먼저 정한다.
  점 찍기, 선/면 정점 입력과 완료, 기존 정점 이동·삽입·삭제, 선택 피처 삭제를
  공용 명령으로 수행한다. 폴리곤의 폐합과 유효성을 커밋 전에 검사한다.
- GUI 버튼뿐 아니라 CLI/Lua를 포함한 도형 변경 명령 경계에서도 잠금을 검사한다.
  작업 시작 시와 변경 게시 시에 상태를 확인해 작업 중 Lock으로 바뀐 레이어에
  비동기 결과가 적용되지 않게 한다. 도형을 변경하는 undo/redo도 같은 정책을 따른다.
- 그리는 중 Lock하면 입력 완료/취소를 먼저 선택한다. 이미 적용했으나 저장하지
  않은 변경이 있으면 저장 후 잠금/변경 폐기 후 잠금/돌아가기를 제공한다.
  저장 실패 시 Unlock과 미저장 상태를 유지한다. 무관한 레이어의 draft를 함께
  커밋/폐기하지 않도록 현재 프로젝트 단위 트랜잭션과 레이어 단위 세션의 경계를 보강한다.
- 저장 대상과 임시 레이어 여부를 표시한다. 소스 파일을 즉시 덮어쓰지 않고 저장
  동작을 분리하며, 새 레이어는 첫 저장 시 경로를 지정한다. 인덱스·선택·레이블·렌더
  캐시는 추가/수정/삭제와 undo/redo 후 함께 갱신한다.

## 2. CSV/TSV 점 목록 → 닫힌 도형

업무 흐름은 `파일 미리보기 → 인코딩/필드/X/Y/CRS 지정 → 점 레이어 추가 → 점 목록에서
선택 → 연결 순서 확인 → 폴리곤 미리보기 → 새 폴리곤 레이어 생성 → 레이블/내보내기`다.
CSV의 오류 행과 필드 형식 정책은 [D 기본 계획](milestone-d-practical-workflows.md)을 따른다.

- 점 목록과 지도 선택을 연결하되 선택 집합과 정점 순서는 별도로 관리한다.
  기본 순서는 원본 행 순서이며, 선택 순서/사용자가 지정한 순번 필드/목록의
  위아래 이동으로 연결 순서를 명시할 수 있게 한다. 정렬된 화면의 우연한 순서나
  최근접 자동 연결로 경계를 추측하지 않는다. 순번 중복·누락 정책을 확인한다.
- 첫 버전은 한 그룹의 선택 점으로 외곽 링 하나를 가진 2D Polygon 한 개를 생성한다.
  서로 다른 좌표 3개 이상이 필요하며 마지막 점에서 첫 점으로 한 번만 폐합한다.
  이미 반복된 시작점은 정규화하고 나머지 중복점·일직선·면적 0·자기 교차는
  진단하여 확정을 막는다. 도넛 구멍과 다중 외곽 링 자동 추정은 후속으로 둔다.
- 기존 점 레이어는 보존하며 새 폴리곤 레이어로 결과를 만든다. 생성 결과는 데이터가
  있으므로 기본 Lock이다. 기존 폴리곤 레이어에 추가하려면 해당 레이어 Unlock,
  형상 타입·CRS 호환과 필드 매핑을 확인한다. 원본 점 수정에 자동 추종하지 않으며
  재생성은 별도 동작이다. 원본 행 식별자·연결 순서는 작업공간 메타데이터에 남긴다.
- 여러 폴리곤은 사용자가 그룹별로 확정하거나 명시적 그룹 ID+순번 필드로 배치
  생성한다. 배치는 후속이며 최초 수용 범위는 수동 선택 한 그룹이다.
- 원본 점의 속성을 한 폴리곤에 임의로 복사하지 않는다. 새 도형 ID와 레이블은
  입력받고, 공통값 복사/사용자 지정 등 속성 결정 규칙을 명시한다. 서로 다른 값이
  있는 필드는 충돌을 표시한다. 지도에서는 임시 선·폐합선과 확정될 면을 미리 본다.

## 3. 자동 레이블 데이터

기존 이름/번호 열 선택, 필드 템플릿 조합, 접두어+순번 생성을 제공한다. 예를 들어
`점-{관리번호}` 또는 `P001`을 새 문자열 필드 `label_text`에 생성하고 레이어 레이블
설정을 이 필드에 연결한다. 기존 필드 덮어쓰기는 명시적 선택으로만 허용한다.
생성 순번은 확인된 원본 행 순서를 기준으로 한 번 생성해 속성으로 저장한다.
필터·정렬·피처 삭제마다 번호를 다시 매기지 않는다.

빈 이름 처리와 중복 레이블 허용/차단을 미리 선택하고 결과를 미리 본다. 폴리곤은
사용자가 지정한 도형명 또는 순번을 사용하며, 내부 대표점 배치에 기존 경계를
재사용한다. 문자열 속성 생성과 지도 표시 설정은 별개의 저장 대상으로 취급한다.

SHP에는 일반 문자열 속성으로 `label_text`를 내보낼 수 있지만, 수신 앱에서 지도와
동일하게 레이블을 켜거나 글꼴·배치·회전을 자동 복원한다고 약속하지 않는다. 이
표시 설정은 작업공간에 저장한다. 별도의 레이블 점 SHP를 원하는 경우 텍스트와
대표점 좌표를 가진 Point 레이어를 만들어 별도 출력한다. CAD 문자 엔티티가 필요한
납품은 기존 DXF 경로를 사용한다.

## 4. 기존 데이터 변환 및 SHP export

CSV 점과 생성 폴리곤 외에도 현재 읽을 수 있는 SHP/GeoPackage/PostGIS 등 벡터
레이어를 선택해 SHP로 내보내는 공통 경로를 제공한다. CRS가 없는 데이터는 먼저
지정해야 하며 geometry 없는 표만으로 도형을 추측해 SHP를 만들지 않는다.

- 출력 대화상자에서 단일 레이어, 전체/선택/필터 범위, 출력 CRS, 필드와 인코딩을
  지정한다. Point/Line/Polygon이 섞였으면 타입별 별도 출력 또는 명확한 거부를
  제공한다. 현재 writer의 더 엄격한 동일 형상 타입 검사도 사전 점검에 반영한다.
- 호환성을 위해 DBF 필드명은 ASCII 10자 이내로 명시 매핑하고 원래 이름과의
  대응표를 제공한다. 한글 긴 필드명을 조용히 자르거나 충돌 이름으로 내보내지 않는다.
  문자열 폭·숫자 폭/정밀도·지원하지 않는 속성 타입은 변환 미리보기에서 검증한다.
- UTF-8을 기본으로 `.cpg`를 기록한다. CP949는 새 옵션으로 구현·왕복 검증하고
  표현 불가능한 문자가 있으면 실패 원인과 필드를 보고한다. 날짜/시각·null·큰 정수
  등 손실 가능 값의 변환 정책을 확정하기 전에는 저장을 진행하지 않는다.
- `.shp/.shx/.dbf/.prj/.cpg` 묶음을 납품 단위로 취급한다. 알려진 CRS를 `.prj`에
  기록하고 작은 샘플로 재개방해 좌표·한글·건수·필드 대응을 검증한다. 상호 운용성을
  위해 `.shp`/`.dbf` 각각 2GB 제한을 적용하고 초과 시 GeoPackage를 안내한다.
- 다중 파일은 단일 파일처럼 원자적 교체를 보장하지 못한다. 새 대상 디렉터리의
  임시 영역에서 모두 생성·검증한 뒤 게시한다. 첫 버전은 기존 파일 묶음 덮어쓰기를
  거부한다. 실패/취소 시 이번 작업의 임시 산출물만 정리하고 기존 파일은 보존한다.
- 빈 레이어도 형상 스키마를 명시해 출력할 수 있도록 현재의 첫 피처 추론 의존을
  보강한다. 0건 결과와 빈 필터/선택을 구분해 의도한 빈 출력을 확인하게 한다.

포맷 제약 근거: [GDAL 공식 Shapefile 문서](https://gdal.org/en/stable/drivers/vector/shapefile.html)의
Creation Issues, Encoding, Field sizes, Size Issues를 확인했다. 위 설계는 일반 DBF
호환성을 기준으로 하며 특정 GDAL 버전의 필드 별칭 확장에 의존하지 않는다.

## 구현 순서와 수용 기준

기존 D1~D6 번호는 유지하고, D0(편집 잠금)과 D1a~c를 추가하며 D5의 출력 범위를
SHP까지 넓힌다. 아래 순서로 기존 D2~D4와 병행할 수 있다.

| 단계 | 구현 단위 | 반드시 확인할 결과 |
| --- | --- | --- |
| D0 | 소스 능력/잠금 분리, 빈 레이어 생성, 추가·수정·삭제 UI와 명령 | 기존 레이어 Lock, 확인된 빈 레이어 Unlock, 읽기 전용 해제 차단, 다른 레이어 영향 없음, 변경/저장/취소/undo/redo 및 잠금 우회 차단 |
| D1 | CSV/TSV 점 입력 | 한글·선행 0·X/Y/CRS·오류 행·취소·대형 입력의 기존 D1 수용 기준 통과 |
| D1a | 점 목록 선택과 폴리곤 생성 | 순서 변경 결과 일치, 정확한 폐합, 3점 미만·일직선·중복·자기 교차 거부, 원본 점 보존, 확정/취소와 결과 기본 Lock |
| D1b | 자동 레이블 속성 및 표시 | 템플릿/순번의 결정성, null/중복/덮어쓰기 처리, 점·폴리곤 표시, 정렬 후 번호 보존, 내보낸 문자열 유지 |
