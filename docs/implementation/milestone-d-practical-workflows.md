# 마일스톤 D — CSV와 업무대장을 활용한 실무 작업

상태: 구현 완료 / 수용 시나리오 검증 진행 중 — 2026-10-24

현재 구현: 공용 명령 계층에 도형 잠금, CSV/TSV 점 가져오기와 행 오류 보고,
순서 기반 단일 폴리곤 생성, 레이블 필드 생성, 키 조인, 비변경 검수, 평면
길이·면적 계산을 추가했다. native CLI의 `import-csv`, `join`, `validate`,
`measure`와 필터 CSV 납품, GUI의 레이어 잠금·CSV 미리보기·업무 워크플로우,
명시적 형상 타입을 가진 빈 레이어의 GeoPackage/SHP 저장을 연결했다.
여러 CSV를 한 점 레이어로 합치고, 그룹별 볼록 외곽선과 `shape_id`를 생성한다.
생성한 경계로 추가한 SHP 면을 잘라 식별자별 레이어로 분리할 수 있다. Lua 조건으로
피처를 필터하거나 Lua가 반환한 식별자별로 여러 레이어로 나눌 수도 있다.
대화형 입력은 [ADR 0030](../decisions/0030-milestone-d-interactive-bounds-and-join-policy.md)의
행·파일 상한을 적용하고 중복 대장 키는 출력 전에 차단한다. 실제 업무 샘플을
이용한 GUI 납품 시나리오와 OS별 배포 검증은 별도로 남아 있다.

native CLI 재현 명령은 다음과 같다.

```text
gis-cli import-csv --input points.csv --output points.gpkg --x-field X --y-field Y --crs EPSG:4326
gis-cli polygon --input points.gpkg --layer csv_points --feature-ids 1,2,3 --output area.gpkg
gis-cli join --input assets.gpkg --table inspections.csv --layer-key 관리번호 --table-key 관리번호 --output joined.gpkg
gis-cli validate --input joined.gpkg --required 관리번호,등급 --unique 관리번호 --output validation.csv
gis-cli measure --input area.gpkg --output measured.gpkg
gis-cli filter --input joined.gpkg --field 등급 --value A --output selected.csv
gis-cli aggregate --input measured.gpkg --group 등급 --sum area --output summary.csv
gis-cli import-csv --input west.csv --input east.csv --output survey.gpkg --output-layer survey --x-field X --y-field Y --crs EPSG:5186 --boundary --boundary-group block
gis-cli split-boundary --input parcels.shp --boundary-file survey.gpkg --boundary-layer survey_boundaries --output parcel_groups.gpkg
```

합성 입력 성능 기준은 다음 벤치마크로 재현한다. 100만 행은 장비의 최대 메모리와
취소 응답을 확인하는 장시간 측정용이며, 일반 회귀에서는 10만 행 1회 측정을 사용한다.

```text
go test ./internal/commands -run '^$' -bench 'ImportCSVPoints(100k|1M)' -benchtime=1x -benchmem
```

2026-10-24 Apple M3 arm64 측정값은 10만 행 51.8ms / 80.0MB / 1,400,079회
할당, 100만 행 588.2ms / 798.9MB / 14,000,084회 할당이었다. 입력 전체를
메모리에 보관하는 현재 레이어 모델의 특성상 100만 행은 약 0.8GB를 사용하므로
GUI는 10만 행·16 MiB 상한을 적용하고 취소·분할 처리를 안내한다.
UI·메모리 경계와 UTF-8 유효성 검사 보강 후 같은 Apple M3에서 2026-10-24
재측정한 값은 10만 행 60.9ms / 80.0MB, 100만 행 584.6ms / 798.9MB였다.
이는 Go 할당 총량이며
프로세스 최대 상주 메모리와 같지 않다.

제품 기준은 [실행 명세](../../desktop-gis-codex-brief.md)다. 이번 마일스톤은
측량점·시설물 좌표 목록과 업무대장을 지도 데이터로 연결하고 검수한 뒤 납품하는
업무를 대상으로 한다. 아래 수용 기준을 통과하기 전에는 구현 완료로 표시하지 않는다.

레이어별 도형 편집 Lock/Unlock, 빈 레이어 생성, CSV 점 선택으로 폴리곤 생성,
자동 레이블 속성 및 SHP 출력에 대한 추가 요청은
[편집·CSV 도형·SHP 보완 검토](milestone-d-editing-csv-shapefile.md)를 따른다.
기존 D1~D6 번호를 유지하며 D0·D1a~c를 추가하고 D5에 SHP 납품을 포함한다.

## 우선순위와 완료 기준

| 순서 | 목표 | 실제 업무 예 | 완료 기준 |
| --- | --- | --- | --- |
| D0 / 필수 | 레이어별 도형 편집 Lock/Unlock | 기존 자료의 실수 편집을 막고 빈 레이어에 점·선·면 작성 | 기본 Lock, 쓰기 가능 빈 레이어 Unlock, 도형 추가·편집·삭제와 저장·취소, 읽기 전용 해제 및 명령 우회 차단을 확인한다. |
| D1 / 필수 | CSV/TSV 좌표 데이터 추가 | 측량점, 시설물 위치, 현장 조사 좌표 목록을 점 레이어로 표시 | 미리보기에서 구분자·헤더·인코딩·필드 형식·X/Y·원본 CRS를 확정하고 가져온다. 정상/거부 행 수와 행 번호별 원인을 확인하며 결과를 GeoPackage로 저장·재개방한다. |
| D2 / 필수 | 업무대장 속성 조인 | 관리번호로 시설물 도형에 점검일·등급·담당 구역 연결 | 양쪽 키·추가 필드·필드명 충돌 정책을 선택한다. 매칭/미매칭/중복을 미리 집계하고 결과를 새 레이어로 생성한다. 입력 원본은 보존한다. |
| D3 / 필수 | 필드 계산과 면적·길이 산출 | 필지 면적 합계, 구간 길이, 관리번호 조합, 등급별 분류 | 새 필드/기존 필드 및 적용 대상 전체/선택/필터를 명시한다. 계산 CRS와 m·m² 등 단위를 기록하고 알려진 형상으로 수치를 검증한다. 오류나 취소 시 부분 변경을 남기지 않는다. |
| D4 / 필수 | 업무 데이터 검수 | 좌표 누락, 관리번호 중복, 필수값 누락, 잘못된 형상 확인 | 규칙별 건수·피처 ID·원인을 보여 주고 지도 선택과 연결한다. 검수 결과를 CSV로 내보내며 자동 수정 없이 사용자가 수정 후 재검사한다. |
| D5 / 필수 | 선택/필터 결과 납품과 집계 | 특정 구역의 점검 대상만 전달하고 등급별 수량·면적 집계 | 대상 범위·필드·CRS·인코딩과 출력 건수를 미리 확인한다. CSV 속성표, GeoPackage, SHP, 기존 DXF 경로를 연결하고 그룹별 개수·숫자 합계를 표/CSV로 제공한다. |
| D6 / 후속 | 반복 작업 설정 재사용 | 매달 같은 양식으로 받은 점검 CSV 갱신 | 입력 매핑·조인·계산·검수·출력 옵션을 버전이 있는 설정으로 저장한다. 새 파일의 스키마 차이를 검증하고 실행 기록에 건수·실패 원인을 남기며 동일 설정을 CLI에서 재현한다. |

편집 정책 D0을 먼저 정립하고 CSV 입력 D1을 연결한다. D1a(점 선택→폴리곤),
D1b(자동 레이블), D1c(SHP 출력 보강)도 필수 범위다. D1과 D2를 연결하면 “좌표 CSV → 지도 확인 → 업무대장
조인 → GeoPackage 저장”의 첫 실무 경로가 성립한다. D0~D5(D1a~c 포함)를 D의 필수 완료
범위로 삼고 D6은 별도 후속으로 추적한다.

## 입력과 데이터 정확성 규칙

- CSV와 탭 구분 TSV를 지원한다. 따옴표 안의 구분자·줄바꿈, UTF-8 BOM,
  빈 셀, 동일/빈 헤더, 잘못된 행 길이를 소형 샘플로 검증한다.
- UTF-8과 CP949를 시작 검증 대상으로 한다. 감지는 제안으로만 표시하고 사용자가
  확정하며, 해석 실패를 대체 문자로 조용히 덮지 않는다.
- 필드 형식은 미리보기에서 제안하고 확정할 수 있게 한다. 관리번호와 지번은
  문자열로 보존해 선행 0을 잃지 않는다. 빈 값과 숫자 0을 구분하고 숫자/날짜의
  해석 규칙을 명시한다. 미리보기 밖의 형식 오류도 행 번호와 함께 보고한다.
- X/Y 열과 원본 CRS는 명시적으로 지정한다. 경위도처럼 보이는 값만으로 CRS를
  확정하지 않는다. EPSG:4326의 경도/위도 및 투영 좌표의 X/Y 매핑은 축 순서가
  드라이버를 통과한 뒤에도 유지되는지 알려진 좌표로 검증한다.
- 빈 좌표, 비숫자, NaN/Inf, CRS 유효 범위를 벗어난 값을 검수한다. 잘못된 행은
  기본적으로 완료를 막고, 사용자가 제외를 선택할 때만 제외 건수와 보고서를
  남겨 가져온다. 취소 시 불완전 레이어를 프로젝트에 추가하지 않는다.
- D2는 다수 피처 대 단일 대장 행 조인부터 지원한다. 대장 쪽 중복 키는 실행을
  막고 해결하도록 안내한다. 빈 키는 서로 매칭하지 않는다. 공백 제거 등 키
  정규화는 옵션으로 명시하며 기본값은 원문 일치다. 미매칭 피처는 유지하고
  추가 속성을 빈 값으로 두며, 연결되지 않은 대장 행도 별도로 집계한다.
- D3의 최초 측정 방식은 적합한 투영 CRS에서의 평면 계산으로 한정한다. 경위도
  좌표의 도 단위 계산을 m/m²로 표시하지 않는다. 측정 CRS·단위와 넓은 범위에서의
  투영 왜곡 한계를 결과에 기록하며 측지 계산은 후속 범위다.
- CSV 출력은 UTF-8을 기본으로 하고 CP949는 표현 가능한 문자열을 검증한다.
  스프레드시트에서 수식으로 해석될 수 있는 문자열은 안전 출력 옵션과 원문
  보존 옵션의 차이를 설명하고 선택하게 한다.

## 처리 경계와 성능

표 파싱/쓰기와 인코딩 처리는 드라이버 경계에 두고 GUI 안에서 좌표 변환이나 조인을
구현하지 않는다. 공용 명령 API가 입력 옵션 검증, CRS 변환, 결과 레이어 생성과
취소를 담당한다. GUI는 미리보기·진행률·오류 보고를 제공하고 CLI는 같은 옵션과
결과 보고 모델을 사용한다. Lua는 제한된 피처별 필터·분리 평가기로 사용한다.

미리보기와 오류 상세는 페이지·행 수·바이트 한도를 둔다. 파일 읽기는 순차 처리하며
조인 인덱스에도 메모리 예산을 적용한다. 예산을 넘으면 작업을 중단하고 입력 축소나
분할을 안내한다. 전체 파일을 한 번에 UI로 전달하지 않는다. 10만/100만 행의 합성
데이터로 처리 시간·최대 메모리·취소 응답을 측정하고 장비와 설정을 기록한다.
수치 목표는 첫 기준 측정 후 정하며, 무제한 입력 처리를 약속하지 않는다.

## 수용 시나리오

1. 한글 이름과 선행 0 관리번호를 가진 좌표 CSV를 UTF-8/CP949로 준비한다.
   EPSG:4326과 EPSG:5186 샘플을 각각 추가하고, 알려진 좌표·속성·건수를 확인한다.
2. 별도의 점검 대장을 관리번호로 연결한다. 중복 키 차단, 빈 키 미매칭,
   대장/도형 양쪽 미매칭 보고, 필드명 충돌 처리를 확인한다.
3. 기준 직사각형과 선분으로 면적·길이를 검증하고 선택된 피처만 계산한다.
   잘못된 식·형식 오류·취소 시 원래 속성이 유지되는지 확인한다.
4. 필수값 누락/중복/잘못된 형상을 가진 합성 입력으로 검수 목록과 지도 선택을
   확인한다. 원본을 자동 수정하지 않는지 확인한다.
5. 필터 결과를 CSV/GeoPackage/SHP/DXF로 출력해 건수·한글·CRS·레이블 문자열을 검증한다.
   집계 값과 개별 레코드를 대조하고 GUI/CLI의 동일 입력 결과를 모델로 비교한다.
6. 대형 합성 CSV에서 진행률·취소·메모리 예산·오류 보고 한도를 검증한다.

테스트에는 재배포 가능한 작은 합성 데이터만 저장한다. 실제 업무 자료 수용은
사용자가 제공한 자료와 허용 범위 안에서 별도로 기록한다.

## 이번 범위에서 제외

Excel 통합문서 직접 연결, 주소 지오코딩/외부 API, 실시간 양방향 대장 동기화,
다대다 조인, 래스터 분석, 네트워크 경로 분석, 인쇄 레이아웃은 후속 검토 대상이다.
기존 마일스톤 C 잔여 수용 검증과 OS별 패키지 검증을 D 완료로 대체하지 않는다.
